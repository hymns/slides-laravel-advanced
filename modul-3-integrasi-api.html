RESTful best practices

Kata nama dalam URL, kata kerja dalam method

REST (Representational State Transfer): setiap URL ialah satu resource (benda), dan method HTTP ialah tindakan ke atasnya.

TindakanRESTfulElakkan
Senarai invois sayaGET /api/v1/invoicesGET /api/getMyInvoices
Satu invoisGET /api/v1/invoices/7GET /api/invoice?id=7&action=view
Bayar invoisPOST /api/v1/paymentsGET /api/invoices/7/pay
Log keluar (padam token)DELETE /api/v1/tokens/currentPOST /api/logout?token=…
  1. Kata nama jamak: invoices, payments. Huruf kecil, tiada kata kerja.
  2. GET tidak pernah mengubah data. Pelayar, proxy dan crawler boleh mengulang GET sendiri.
  3. Token dalam header Authorization, bukan dalam URL: URL tercatat dalam log pelayan dan sejarah pelayar.
Tanya: "Bayar" ialah kata kerja. Jadi resource apa yang dicipta bila pelajar membayar? Jawapan: satu Payment baru, oleh itu POST /payments.

namespace App\Http\Resources;

use Illuminate\Http\Request;
use Illuminate\Http\Resources\Json\JsonResource;

final class InvoiceResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id'         => $this->id,
            'number'     => $this->number,
            'type'       => $this->type,
            'amount'     => $this->amount,
            'due_date'   => $this->due_date->toDateString(),
            'paid_at'    => $this->paid_at?->toIso8601String(),
            'is_overdue' => $this->paid_at === null
                && $this->due_date->isPast(),
        ];
    }
}

Bila perlu versi baru?

PerubahanVersi baru?

User dengan HasApiTokens

app/Models/User.php


namespace App\Models;

use Illuminate\Database\Eloquent\Attributes\Fillable;
use Illuminate\Database\Eloquent\Attributes\Hidden;
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Relations\BelongsTo;
use Illuminate\Foundation\Auth\User as Authenticatable;
use Illuminate\Notifications\Notifiable;
use Laravel\Sanctum\HasApiTokens;

#[Fillable(['name', 'email', 'password'])]
#[Hidden(['password', 'remember_token'])]
class User extends Authenticatable
{
    use HasApiTokens, HasFactory, Notifiable;

    protected function casts(): array
    {
        return ['email_verified_at' => 'datetime', 'password' => 'hashed'];
    }

    public function student(): BelongsTo
    {
        return $this->belongsTo(Student::class);
    }

    public function isBursary(): bool
    {
        return $this->role === 'bursary';
    }
}
  • HasApiTokens beri method createToken(), tokens() dan currentAccessToken()
  • #[Fillable] dan #[Hidden] ialah attribute PHP (PHP 8.0+): label pada class, bukan komen. Semasa model dicipta, Laravel baca label itu melalui Reflection dan gabungkan senarainya ke dalam $fillable dan $hidden. Hasilnya sama seperti protected $fillable = [...]; nama yang sepadan hanya konvensyen Laravel
  • role sengaja tiada dalam senarai fillable. Sebabnya dalam Bahagian Security Hardening (Hari 3)
Tanpa trait: install:api sudah beri amaran "Please add the [Laravel\Sanctum\HasApiTokens] trait to your User model".
Token-based auth

Endpoint log masuk untuk aplikasi mudah alih

app/Http/Controllers/Api/V1/TokenController.php


namespace App\Http\Controllers\Api\V1;

use App\Http\Controllers\Controller;
use App\Models\User;
use Illuminate\Http\JsonResponse;
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Hash;
use Illuminate\Validation\ValidationException;

final class TokenController extends Controller
{
    public function store(Request $request): JsonResponse
    {
        $data = $request->validate([
            'email' => ['required', 'email'],
            'password' => ['required', 'string'],
            'device_name' => ['required', 'string', 'max:100'],
        ]);
        $user = User::where('email', $data['email'])->first();

        if (! $user || ! Hash::check($data['password'], $user->password)) {
            throw ValidationException::withMessages(['email' => 'Emel atau kata laluan salah.']);
        }
        $abilities = $user->isBursary()
            ? ['invoices:read', 'reports:read']
            : ['invoices:read', 'payments:create'];
        $token = $user->createToken($data['device_name'], $abilities, now()->addDays(30));

        return response()->json(['token' => $token->plainTextToken, 'abilities' => $abilities], 201);
    }
}
  1. Mesej sama untuk emel tiada dan kata laluan salah: penyerang tidak boleh teka emel mana yang wujud
  2. Abilities = senarai perkara yang token ini dibenarkan. Pelajar boleh bayar; Bendahari boleh baca laporan
  3. Tamat tempoh 30 hari. Telefon hilang? Token mati sendiri
  4. plainTextToken hanya wujud sekali, dalam response ini
Kenapa tokens, bukan login? Log masuk = cipta token, jadi POST /api/v1/tokens. Log keluar = padam token, jadi DELETE /api/v1/tokens/current. Portal Bendahari pula guna POST /login, yang mencipta sesi cookie, bukan token.

namespace App\Http\Controllers\Api\V1;

use App\Http\Controllers\Controller;
use App\Models\{Invoice, Payment};
use Illuminate\Http\Request;
use Illuminate\Support\Facades\DB;

final class PaymentHistoryController extends Controller
{
    public function index(Request $request, Invoice $invoice)
    {
        $sort = $request->query('sort', 'paid_at');

        return DB::select("select * from payments
            where invoice_id = {$invoice->id} order by $sort");
    }

    public function update(Request $request, Payment $payment)
    {
        $payment->forceFill($request->all())->save();

        return $payment;
    }
}

// routes/api.php, di luar semua kumpulan:
Route::get('invoices/{invoice}/payments', [PaymentHistoryController::class, 'index']);
Route::get('payments/{payment}/update', [PaymentHistoryController::class, 'update']);
  1. Tiada auth:sanctum dan tiada policy: sesiapa boleh baca bayaran sesiapa: IDOR (Insecure Direct Object Reference)
  2. $sort masuk terus ke SQL: SQL injection. Guna Rule::in([...]) dan orderBy()
  3. forceFill($request->all()): ubah amount dan paid_at. Guna validate()
  4. GET mengubah data, dan tiada throttle
  5. Pulangkan baris DB / model mentah: semua kolum bocor. Guna PaymentResource
