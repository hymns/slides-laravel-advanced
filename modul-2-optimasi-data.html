Bila peraturan berubah, contohnya invois yang dibatalkan (cancelled_at) tidak lagi dikira tertunggak, kita perlu cari dan ubah setiap tempat. Satu tertinggal = laporan Bendahari salah.
Penyelesaian: beri syarat itu satu nama dalam model: Invoice::outstanding(). Ini dipanggil query scope.
Query scope

Beri nama kepada syarat

app/Models/Invoice.php


namespace App\Models;

use App\Enums\FeeType;
use Illuminate\Database\Eloquent\Attributes\Scope;
use Illuminate\Database\Eloquent\Builder;
use Illuminate\Database\Eloquent\Model;

class Invoice extends Model
{
    // $fillable, $casts, payments(), student(): seperti sebelum ini

    #[Scope]
    protected function outstanding(Builder $query): void
    {
        $query->whereNull('paid_at');
    }

    #[Scope]
    protected function overdue(Builder $query): void
    {
        $query->outstanding()
            ->where('due_date', '<', today());
    }

    #[Scope]
    protected function ofType(Builder $query, FeeType $type): void
    {
        $query->where('type', $type);
    }
}
  1. #[Scope] tandakan method sebagai scope (Laravel 12 ke atas)
  2. Parameter pertama sentiasa Builder $query: query yang sedang dibina
  3. Scope boleh panggil scope lain: overdue() guna outstanding()
  4. Parameter tambahan selepas $query: ofType(FeeType $type)
Method protected, tetapi dipanggil seperti method statik: Invoice::outstanding(). Laravel yang menyambungkannya.
Kod lama mungkin guna gaya scopeOutstanding($query). Hasilnya sama; projek baru guna #[Scope].

Subquery

Bilakah dan bagaimana pelajar terakhir membayar?

use App\Enums\PaymentMethod;
use App\Models\{Payment, Student};

$students = Student::query()
    ->withMax('payments', 'paid_at')
    ->addSelect(['last_method' => Payment::select('method')
        ->whereColumn('student_id', 'students.id')
        ->latest('paid_at')
        ->limit(1),
    ])
    ->withCasts(['last_method' => PaymentMethod::class])
    ->orderBy('matric')->limit(50)->get();

SQL sebenar: 1 query


select `students`.*,
  (select max(`payments`.`paid_at`) from `payments` where `students`.`id` = `payments`.`student_id`) as `payments_max_paid_at`,
  (select `method` from `payments` where `student_id` = `students`.`id` order by `paid_at` desc limit 1) as `last_method`
from `students` order by `matric` asc limit 50
  1. withMax: tarikh terakhir. Satu nilai agregat, cukup.
  2. Kaedah bayaran terakhir bukan agregat. Kita perlukan kolum lain dari baris terkini: itu kerja subquery.
  3. whereColumn: bandingkan dua kolum, bukan kolum dengan nilai
  4. withCasts: hasil subquery ialah string 'fpx'. Tanpanya, $casts model tidak terpakai.
Tanpa subquery: with('payments') muat setiap bayaran semua pelajar ke memori, semata-mata untuk ambil satu.
Output "2026-11-22 00:00:00" dan PaymentMethod::Fpx ialah hasil sebenar bagi A23CS00001 dalam data ujian. Uji tanpa withCasts: last_method = 'fpx' (string).

Rollback berjaya. Foreign key kini guna invoices_student_id_index.

Kenapa: migration asal ada foreignId('student_id')->constrained(), jadi foreign key wajib ada index yang bermula dengan student_id. Composite itu kini satu-satunya index untuk foreign key, jadi ia tidak boleh dibuang. Tanpa foreign key, ralat ini tidak berlaku (diuji). Sentiasa uji migrate:rollback sebelum deploy.
Soalan biasa: "Kenapa tidak biarkan down() kosong, langkau dropIndex?" Diuji: rollback lulus, tetapi index kekal dalam DB. Bila php artisan migrate dijalankan semula, up() gagal dengan SQLSTATE[42000] 1061 Duplicate key name 'invoices_student_id_paid_at_due_date_index'. down() mesti kembalikan DB kepada keadaan sebelum up(), supaya migrate:fresh, migrate:refresh dan deploy semula selepas rollback berjaya.

Race condition · garis masa

Kenapa kedua-dua klik lepas semakan

Punca: semakan paid_at dan caj bank berlaku sebelum sebarang lock. Dua request baca keadaan yang sama, dan kedua-duanya betul pada saat itu.

Lock S (shared) datang dari semakan foreign key: bila insert payment dengan invoice_id = 16, InnoDB kunci baris invois 16 supaya ia tidak dipadam. Lock X (exclusive) diperlukan untuk update. Dua S, kedua-duanya mahu X: saling menunggu. Disahkan dengan SHOW ENGINE INNODB STATUS.

public function pay(Student $student, PaymentData $data): Payment
{
    return DB::transaction(function () use ($student, $data) {
        $invoice = Invoice::lockForUpdate()
            ->findOrFail($data->invoiceId);
        if ($invoice->paid_at !== null) {
            throw InvoiceAlreadyPaidException::for($invoice);
        }
        $amount = $invoice->amount + $this->penalties->for($invoice, now());
        $reference = $this->processor->charge($invoice, $data->method, $amount);
        $payment = $this->invoices->recordPayment($invoice, [
            'student_id' => $student->id, 'method' => $data->method,
            'amount' => $amount, 'reference' => $reference, 'paid_at' => now(),
        ]);
        PaymentReceived::dispatch($payment);
        return $payment;
    });
}

private function payNow(Student $student, PaymentData $data): Payment
{
    $invoice = $this->invoices->findOrFail($data->invoiceId);
    if ($invoice->paid_at !== null) {
        throw InvoiceAlreadyPaidException::for($invoice);
    }
    $amount = $invoice->amount + $this->penalties->for($invoice, now());
    // panggilan ke bank: di luar transaksi DB
    $reference = $this->processor->charge($invoice, $data->method, $amount);
    return DB::transaction(function () use ($invoice, $student, $data, $amount, $reference) {
        $payment = $this->invoices->recordPayment($invoice, [
            'student_id' => $student->id, 'method' => $data->method,
            'amount' => $amount, 'reference' => $reference, 'paid_at' => now(),
        ]);
        PaymentReceived::dispatch($payment);
        return $payment;
    }, attempts: 3);
}
